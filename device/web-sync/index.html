NDEF note — a short text or link the tag carries

An NDEF note is the standard "message" stored on NFC tags: up to 200 bytes of plain text or an http(s) link. Queue one here, send it to the device, and the device can either write it onto a blank NTAG215 tag (any NFC phone can then read it) or emulate it as a virtual tag. Exactly the note below is what the device menu's Write / Emulate / Clear NDEF note items act on.

Write to NTAG215 arms the writer — tap a blank tag on the device antenna and the note is written and read-back verified. Emulate note presents it as a virtual tag instead. On the handheld these mirror its NDEF menu items; the screenless OpenTag Mini has them only here.

How the note flow works, step by step

1. Pick Text or Web URL, type the content, press Queue note — it is only staged in this page so far.
2. Send note now pushes it to the device over BLE; the device stores it (survives reboots) and shows it at the bottom of its menu.
3. On the device, Write NDEF note copies it onto a blank NTAG215 tag, Emulate NDEF note makes the device pretend to be a tag carrying it, and Clear NDEF note wipes it.
4. Clear device note above does the same clear remotely — the same command the device menu runs.

Amiibo library

Upload a .zip, loose .bin dumps, or Flipper Zero .nfc files from your own collection — any layout (532/540/572 bytes, padded, or with an N2-style header) is normalized in your browser, validated, then copied to the device over BLE. Kirby Air Riders v3 dumps (1024-byte NTAG I²C page images) are accepted as-is for emulation. Nothing is uploaded to any server.

Back up arms the reader: tap your own amiibo on the device antenna and it is saved to the library under its UID. Inspect identifies any tag — UID, chip type and any NDEF text appear in the log below.

On device

Use only backups of amiibo you own. Amiibo data is Nintendo proprietary; this page and the device never bundle or generate it — you supply your own dumps.

Amiibo database — browse before you sync

Every figure in the open AmiiboAPI database, with box art, series, type and release year. This is the same data your dumps are matched against above, and it needs no device connection. Box-art thumbnails load lazily from AmiiboAPI's image host on GitHub (needs internet; nothing is uploaded or sent anywhere).

Amiibo signing keys (advanced)

OpenTag emulates amiibo — no physical tag writing needed. These keys are only for the optional advanced flow that survives on the device (long-press in its library writes to a real NTAG215, TagMo-style, using your unfixed-info.bin and locked-secret.bin). A combined 160-byte retail key file also works. Files are identified by their embedded type string, stored in the device's NVS, and never bundled with this project or sent anywhere else.

Key state: unknown — connect and check

Only use key files you legally extracted yourself. Uploading them is your responsibility.

Firmware updates over Wi-Fi

Save your Wi-Fi credentials once, then update the OpenTag without a computer: it fetches the newest firmware release from GitHub, flashes only the app partition and reboots — your amiibo library, keys and note survive every update. Credentials live in the device's settings and are only used for updates. The wired one-command updater (tools/update_opentag.py) keeps working without any of this.

Updating needs battery or a charger connected — a power loss during flashing falls back to the previous app on the next boot, but finishing an update is nicer.

OpenTag is an independent open-source project. NFC writes replace the existing NDEF area of the selected NTAG215. Confirm on the device before writing; only use tags you own or are authorized to program.
